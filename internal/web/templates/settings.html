Opening files in your own applications

{{/* M15: a browser cannot launch Aseprite, and this server runs on the NAS — so "Open in…" is a URL scheme, the same mechanism as tel: or vscode://, handled by a small script on your machine. Generated rather than vendored so you can read the whole thing before registering it. */}}

Ambar's “Open in Aseprite / Blender / Godot” buttons use an ambar:// link. Nothing handles that scheme until you install a small helper on the machine you work at — it reads the path out of the link and launches the application. Read it before you register it; it is a dozen lines.

Linux helper macOS helper Windows helper

The links carry the path as your machine sees it, which comes from AMBAR_LOCAL_LIBRARY_PATH. Point that at a mounted location (a mount point, a mapped drive, a UNC path) rather than an smb:// URL — an application cannot open a URL, only a path.
